# CloudWeave Developer API Reference

Welcome to the CloudWeave Developer API documentation. This reference is designed for developers building clients or deploying software against a CloudWeave object storage cluster.

---

## 1. Overview & Architecture Guarantees

CloudWeave is a resilient, multi-tenant distributed object store designed for high availability, strong durability, and horizontal scalability.

### Any-Node Coordination Guarantee
Clients may send **any request** (`PUT`, `GET`, `DELETE`, Range `GET`, Admin management) to **any node** in the cluster. The receiving node automatically coordinates chunk placement across consistent hash rings, queries quorum read/write nodes, and synchronizes metadata across peers transparently. You do not need to understand or track cluster topology.

---

## 2. Authentication & Authorization

All requests to CloudWeave endpoints require API key credentials.

### Authentication Headers
Supply your API key in either of the following HTTP request headers:
- `Authorization: Bearer <YOUR_API_KEY>`
- `X-API-Key: <YOUR_API_KEY>`

### Security & SHA-256 Hashed Persistence
- **Server Key Generation:** Plaintext API keys are generated by the server using `crypto/rand` when calling `POST /admin/keys`. The raw key (e.g. `cw_key_...`) is returned **once** in the creation response.
- **Hashed WAL Storage:** CloudWeave immediately hashes the key using **SHA-256**. Only the `KeyHash` is stored in memory and persisted to the Write-Ahead Log (`metadata.wal`). Plaintext keys are **never** written to disk, logs, or WAL.
- **Verification:** Incoming API keys are hashed via SHA-256 before performing lookup against registered credentials.

### Access Control & Roles
- **Namespace-bound Key:** Permits `PUT`, `GET`, Range `GET`, and `DELETE` operations only for designated namespaces.
- **Admin Key (`IsAdmin`):** Permits operations across all namespaces, as well as cluster administration endpoints (`/admin/join`, `/admin/leave`, `/admin/gc`, `/admin/keys`).

### Rejection Status Codes
- `401 Unauthorized`: Returned when the request is missing an API key or provides an unrecognized API key.
- `403 Forbidden`: Returned when the API key does not have permission for the requested namespace or lacks admin privileges.

## 3. End-to-End TLS Encryption

CloudWeave supports end-to-end TLS encryption across both client-to-node HTTP connections and internal node-to-node mesh transport.

### Enabling TLS
Specify certificate flags or environment variables when starting node processes:

```bash
/node \
  -port=8443 \
  -tls-cert=/etc/ssl/certs/server.crt \
  -tls-key=/etc/ssl/certs/server.key \
  -tls-ca=/etc/ssl/certs/ca.crt
```

- **Flags:** `-tls-cert`, `-tls-key`, `-tls-ca`, `-tls-insecure-skip-verify`
- **Environment Variables:** `CLOUDWEAVE_TLS_CERT`, `CLOUDWEAVE_TLS_KEY`, `CLOUDWEAVE_TLS_CA`, `CLOUDWEAVE_TLS_SKIP_VERIFY`

When TLS is enabled, the node listens via HTTPS for client traffic and node-to-node transport operations (chunk replication, peer manifests, health checks).

## 4. Namespacing & Object Keys

CloudWeave scopes object keys within isolated namespaces (buckets). Two tenants can store objects with identical keys (e.g. `images/avatar.png`) in separate namespaces without collision or unauthorized cross-reading.

### Specifying Namespaces
1. **HTTP Header (Recommended):** `X-Namespace: tenant-alpha`
2. **URL Path Prefix:** `https://<node-addr>/files/tenant-alpha/images/avatar.png`
3. **Fallback:** If neither header nor path prefix specifies a namespace, CloudWeave assigns the object to the `"default"` namespace.

---

## 5. Object Metadata & Content-Type

CloudWeave supports standard object storage metadata preservation.

- **Content Type:** Set on upload via the standard `Content-Type` header (defaults to `application/octet-stream`). Returned in `Content-Type` response header on retrieval.
- **Custom Metadata:** Set on upload by prefixing headers with `X-Meta-` (e.g. `X-Meta-Author: Alice`, `X-Meta-Environment: production`). Returned as `X-Meta-<Key>: <Value>` headers on `GET` and Range `GET`.

## 6. API Endpoint Reference

### Upload Object
`PUT /files/{key}` or `PUT /files/{namespace}/{key}`

Uploads object payload stream.

- **Headers:**
  - `Authorization: Bearer <API_KEY>` or `X-API-Key: <API_KEY>` (Required)
  - `X-Namespace: <namespace>` (Optional)
  - `Content-Type: <mime-type>` (Optional)
  - `X-Meta-<Key>: <Value>` (Optional custom metadata)
- **Response:**
  - `201 Created` — Object stored successfully across cluster quorum.

```bash
curl -X PUT "https://localhost:8080/files/my-tenant/documents/report.pdf" \
  -H "Authorization: Bearer my-api-key" \
  -H "Content-Type: application/pdf" \
  -H "X-Meta-Author: Jane Doe" \
  --data-binary "@report.pdf"
```

---

### Download Object
`GET /files/{key}` or `GET /files/{namespace}/{key}`

Retrieves full object data stream and headers.

- **Headers:**
  - `Authorization: Bearer <API_KEY>` or `X-API-Key: <API_KEY>` (Required)
  - `X-Namespace: <namespace>` (Optional)
- **Response:**
  - `200 OK` — Returns binary stream.
  - Headers set: `Content-Type`, `Content-Length`, `Accept-Ranges: bytes`, and all `X-Meta-*` key-values.

```bash
curl -X GET "https://localhost:8080/files/my-tenant/documents/report.pdf" \
  -H "Authorization: Bearer my-api-key" \
  -o downloaded_report.pdf
```

---

### Partial Content / Range Download
`GET /files/{key}` or `GET /files/{namespace}/{key}`

Retrieves a specific byte range of an object.

- **Headers:**
  - `Authorization: Bearer <API_KEY>` or `X-API-Key: <API_KEY>` (Required)
  - `Range: bytes={start}-{end}` (Required)
- **Response:**
  - `206 Partial Content` — Returns requested byte slice.
  - Headers set: `Content-Range: bytes {start}-{end}/{total_size}`, `Content-Length`.

```bash
curl -X GET "https://localhost:8080/files/my-tenant/documents/report.pdf" \
  -H "Authorization: Bearer my-api-key" \
  -H "Range: bytes=0-1023" \
  -o header_chunk.bin
```

---

### Delete Object
`DELETE /files/{key}` or `DELETE /files/{namespace}/{key}`

Removes object metadata from the cluster.

- **Headers:**
  - `Authorization: Bearer <API_KEY>` or `X-API-Key: <API_KEY>` (Required)
- **Response:**
  - `200 OK` — Object metadata successfully deleted.

```bash
curl -X DELETE "https://localhost:8080/files/my-tenant/documents/report.pdf" \
  -H "Authorization: Bearer my-api-key"
```

---

### Cluster Topology Discovery
`GET /cluster/nodes`

Retrieves an up-to-date JSON list of active node URLs in the cluster topology.

- **Headers:** API Key Credential (Required)
- **Response:** `200 OK` — JSON array of active node addresses `["http://node1:8080", "http://node2:8080"]`.

```bash
curl -X GET "https://localhost:8080/cluster/nodes" \
  -H "Authorization: Bearer my-api-key"
```

---

### Admin: Issue API Key
`POST /admin/keys`

Generates a cryptographically random API key with specified namespace permissions or admin role.

- **Headers:** Admin API Key (Required)
- **Body JSON:** `{"namespaces": ["tenant1", "tenant2"], "is_admin": false}`
- **Response:** `201 Created` — Returns raw key **once** alongside `key_hash`.

```bash
curl -X POST "https://localhost:8080/admin/keys" \
  -H "Authorization: Bearer <ADMIN_KEY>" \
  -H "Content-Type: application/json" \
  -d '{"namespaces": ["finance"], "is_admin": false}'
```

---

### Admin: Revoke API Key
`DELETE /admin/keys`

Revokes an API key credential by key string or SHA-256 `key_hash`.

- **Headers:** Admin API Key (Required)
- **Query Parameters:** `key=<raw_key>` or `key_hash=<sha256_hash>`
- **Response:** `200 OK` — Credential revoked.

```bash
curl -X DELETE "https://localhost:8080/admin/keys?key_hash=e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855" \
  -H "Authorization: Bearer <ADMIN_KEY>"
```

---

### Admin: List API Keys
`GET /admin/keys`

Lists all registered credentials (returns SHA-256 hashes and namespaces; raw keys are never returned).

- **Headers:** Admin API Key (Required)
- **Response:** `200 OK` — Returns JSON list of credential records.

---

### Admin: Mark-and-Sweep Garbage Collection
`POST /admin/gc`

Scans active object manifests across namespaces and deletes orphan storage chunks from physical disk.

- **Query Parameters:** `namespace` (Optional: filter GC sweep)
- **Headers:** Admin API Key (Required)
- **Response:** `200 OK` — Returns count of orphan chunks removed.

---

### Admin: Dynamic Node Join
`POST /admin/join`

Registers a new running node into the cluster live, propagating topology to all peers without restarting existing processes.

- **Query Parameters:** `node_addr=<http://node-ip:port>` (Required)
- **Headers:** Admin API Key (Required)

---

### Admin: Dynamic Node Leave
`POST /admin/leave`

Gracefully removes a node from the cluster topology and triggers under-replication repair workers to re-replicate affected chunks across surviving active nodes.

- **Query Parameters:** `node_addr=<http://node-ip:port>` (Required)
- **Headers:** Admin API Key (Required)

---

### Health Check & Prometheus Metrics
- `GET /health` -> `200 OK` (`"OK"`)
- `GET /metrics` -> Prometheus metrics output

---

## 7. HTTP Error Codes & Definitions

| HTTP Status | Meaning | Reason / Cause |
| :--- | :--- | :--- |
| **`200 OK`** | Success | Request processed successfully. |
| **`201 Created`** | Created | Object uploaded or key issued. |
| **`206 Partial Content`** | Partial Content | Range request fulfilled. |
| **`400 Bad Request`** | Bad Request | Missing file ID, body payload, or invalid arguments. |
| **`401 Unauthorized`** | Unauthorized | Missing or invalid API key credential. |
| **`403 Forbidden`** | Forbidden | Insufficient permissions for namespace or non-admin user calling admin endpoint. |
| **`404 Not Found`** | Not Found | Object key or manifest does not exist. |
| **`416 Not Satisfiable`** | Invalid Range | Requested byte range exceeds file bounds. |
| **`500 Internal Error`** | Server Error | Storage failure, write quorum unfulfilled, or internal error. |

## 8. Getting Started as a Client (Go SDK)

Import `cloudWeave/client` in your Go applications:

```go
package main

import (
	"context"
	"fmt"
	"io"
	"log"
	"time"

	"cloudWeave/client"
)

func main() {
	// Initialize CloudWeave Client with seed endpoints and auto-discovery
	cli, err := client.New(client.Config{
		Endpoints: []string{
			"http://localhost:8080",
		},
		APIKey:              "user-secret-key",
		Namespace:           "my-tenant",
		EnableAutoDiscovery: true,            // Dynamic cluster node discovery
		DiscoveryInterval:   15 * time.Second, // Topology refresh ticker
	})
	if err != nil {
		log.Fatalf("failed to init client: %v", err)
	}
	defer cli.Close()

	ctx := context.Background()

	// 1. Upload Object
	err = cli.Put(ctx, "reports/annual.pdf", []byte("PDF data content..."), client.PutOptions{
		ContentType: "application/pdf",
		Metadata: map[string]string{
			"Author": "Finance Dept",
		},
	})
	if err != nil {
		log.Fatalf("Upload failed: %v", err)
	}
	fmt.Println("Upload successful!")

	// 2. Download Object
	body, info, err := cli.Get(ctx, "reports/annual.pdf")
	if err != nil {
		log.Fatalf("Download failed: %v", err)
	}
	defer body.Close()

	content, _ := io.ReadAll(body)
	fmt.Printf("Downloaded %d bytes (ContentType: %s, Author: %s)\n",
		len(content), info.ContentType, info.Metadata["author"])

	// 3. Delete Object
	if err := cli.Delete(ctx, "reports/annual.pdf"); err != nil {
		log.Fatalf("Delete failed: %v", err)
	}
	fmt.Println("Object deleted!")
}
```
