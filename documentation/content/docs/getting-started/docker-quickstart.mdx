# Docker Quickstart

The fastest way to test CloudWeave's distributed mechanics is with the included Docker Compose configuration.

---

## 1. Standalone Single-Node Mode

To run a single local CloudWeave instance (similar to local MinIO or Redis):

```bash
docker run -d \
  --name cloudweave \
  -p 9000:9000 \
  --memory=256m \
  -e CLOUDWEAVE_API_KEYS="master-secret-key=admin" \
  -v cloudweave_data:/data \
  ghcr.io/jhanvi857/cloudweave:latest
```

When started with no peers, CloudWeave automatically runs in standalone mode with relaxed quorums (`N=1, W=1, R=1`).

Check the node health:

```bash
curl http://localhost:9000/health
```

Expected JSON response:
```json
{
  "status": "ok",
  "node_id": "node-9000",
  "storage_engine": "replication",
  "active_nodes": 1
}
```

---

## 2. 5-Node Distributed Cluster

To experience real distributed consensus, consistent hash ring fan-out, and replica repair, spin up the 5-node cluster:

```bash
# Clone the repository
git clone https://github.com/jhanvi857/CloudWeave.git
cd CloudWeave

# Start the cluster
docker compose up -d
```

Docker Compose spins up 5 isolated node containers on network `cloudweave-net`:

| Container | Host Port | Internal Port | Peers Configured | Quorum Settings |
| :--- | :--- | :--- | :--- | :--- |
| `cloudweave-node1` | `9000` | `9000` | nodes 2, 3, 4, 5 | `N=3, W=2, R=2` |
| `cloudweave-node2` | `9001` | `9001` | nodes 1, 3, 4, 5 | `N=3, W=2, R=2` |
| `cloudweave-node3` | `9002` | `9002` | nodes 1, 2, 4, 5 | `N=3, W=2, R=2` |
| `cloudweave-node4` | `9003` | `9003` | nodes 1, 2, 3, 5 | `N=3, W=2, R=2` |
| `cloudweave-node5` | `9004` | `9004` | nodes 1, 2, 3, 4 | `N=3, W=2, R=2` |

Inspect cluster logs in real time:

```bash
docker compose logs -f node1
```

---

## 3. Web Dashboard

Every CloudWeave node exposes an embedded management dashboard. Open your browser to:

[http://localhost:9000/dashboard](http://localhost:9000/dashboard)

The dashboard displays:
- Active cluster topology and node health statuses.
- Live ring virtual node distribution.
- Recent chunk writes and read operations.
- Interactive chaos button: simulate killing a node and watch the cluster detect the failure and self-heal!

---

## 4. Teardown

To stop and remove all cluster containers and temporary volumes:

```bash
docker compose down -v
```
