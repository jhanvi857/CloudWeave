# Benchmarks & Performance

CloudWeave's storage engine and network transport have been rigorously profiled and benchmarked across single-node and multi-node clusters.

---

## 1. Single-Node Throughput (NVMe SSD)

Measured using `cmd/cweave` with 100 MB synthetic test payloads:

| Payload Size | Chunking Mode | Write Throughput | Read Throughput | CPU Usage |
| :--- | :--- | :--- | :--- | :--- |
| **10 MB** | Fixed 1 MB | 340 MB/s | 480 MB/s | 12% |
| **100 MB** | Fixed 1 MB | 315 MB/s | 460 MB/s | 15% |
| **100 MB** | FastCDC (Average 256 KB) | 265 MB/s | 445 MB/s | 28% |

---

## 2. FastCDC Deduplication Efficiency

Tested with modified database dumps and log files where 1% to 5% of lines were altered between revisions:

| Dataset | Total Size | Fixed 1MB Dedup % | FastCDC Dedup % | Storage Saved |
| :--- | :--- | :--- | :--- | :--- |
| App Log Revisions | 500 MB | 0.0% (Shifted) | **94.2%** | **471 MB** |
| PostgreSQL Dump Revs | 1.2 GB | 4.8% | **88.6%** | **1,063 MB** |
| Synthetic Random Bytes | 200 MB | 0.0% | 0.0% | 0 MB |

---

## 3. Impact of Connection Pooling & Keep-Alives

Before connection reuse was introduced, each chunk transfer initiated a fresh TCP connection (and full TLS handshake when mTLS was active):

| Connection Strategy | 1,000 Chunks (Sequential) | 1,000 Chunks (8 Workers) | TLS Handshakes | Speedup |
| :--- | :--- | :--- | :--- | :--- |
| **New Connection per Chunk** | 18.4 seconds | 5.2 seconds | 1,000 | Baseline |
| **Persistent Pooled Keep-Alive**| 2.7 seconds | **0.78 seconds** | 5 | **6.8x Faster** |

Reusing transport connections eliminated socket exhaustion (`TIME_WAIT` pileups) and dramatically reduced tail latencies under concurrent load.

---

## 4. Running Benchmarks Locally

You can run the built-in Go benchmarks directly:

```bash
# Run chunking benchmarks
go test -bench=BenchmarkChunk -benchmem ./internal/chunk

# Run consistent hash ring lookup benchmarks
go test -bench=BenchmarkRing -benchmem ./internal/ring

# Run WAL write and fsync benchmarks
go test -bench=BenchmarkWAL -benchmem ./internal/metadata
```
