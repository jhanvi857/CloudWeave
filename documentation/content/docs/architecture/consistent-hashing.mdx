# Consistent Hash Ring

CloudWeave avoids central routing bottlenecks by placing data across nodes using a **Consistent Hash Ring** (`internal/ring/ring.go`).

---

## The Virtual Node Architecture

In a naive consistent hash ring with only 1 token per physical host, data distribution is prone to severe hotspots. One node might accidentally receive 60% of the key space, while another receives only 5%.

To guarantee uniform distribution across the 32-bit integer keyspace `[0, 2^32 - 1]`, CloudWeave assigns **150 virtual nodes** (tumblers) per physical node:

```text
Token = Hash(nodeID + "#v" + i)   for i in [0, 149]
```

When looking up the target nodes for a chunk:
1. The chunk ID is hashed to locate its position on the ring.
2. The ring is traversed clockwise using binary search (`sort.Search`).
3. The first `N` **distinct physical nodes** encountered become the designated replica set.

---

## Minimal Remapping on Topology Change

When a node joins or leaves the cluster, standard modulo hashing (`k mod N`) remaps nearly 100% of the entire dataset. 

In contrast, CloudWeave's consistent hash ring guarantees that only:

```text
Fraction of keys remapped ≈ 1 / N_total
```

### Quantitative Benchmark Test (`ring_test.go`)
CloudWeave contains a quantitative test verifying key movement during a node removal:

| Event | Keys Evaluated | Keys Remapped | % Shifted | Theoretical Ideal |
| :--- | :--- | :--- | :--- | :--- |
| **Remove 1 of 5 nodes** | 100,000 | 20,412 | **20.41%** | 20.00% |
| **Remove 1 of 10 nodes** | 100,000 | 10,185 | **10.18%** | 10.00% |

The remaining 80%–90% of keys remain completely unaffected, eliminating cluster-wide cache storms during node failures or scale-out operations.

## Code Example: Ring Placement

```go
// Create a new ring with 150 virtual nodes per host
ring := ring.NewRing(150)

// Register cluster members
ring.AddNode("node1:9000")
ring.AddNode("node2:9001")
ring.AddNode("node3:9002")
ring.AddNode("node4:9003")
ring.AddNode("node5:9004")

// Lookup N=3 replica nodes for a chunk
chunkHash := "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855"
replicas := ring.GetNodesForKey(chunkHash, 3)

// replicas contains 3 distinct physical nodes: ["node2:9001", "node5:9004", "node1:9000"]
```
